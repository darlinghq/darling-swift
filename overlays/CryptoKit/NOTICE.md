# Notices for CryptoKit.framework

`CryptoKit.framework` is compiled from the sources below. None of their files is copied into this repository: they
are read from a checkout of apple/swift-crypto (`SWIFT_CRYPTO_SOURCE_DIR`, see `cryptokit.cmake`) and compiled into
the framework, with the textual rewrite of `rewrite-sources.cmake` applied to a copy of the Swift files in the build
directory. The licence texts are the files of that checkout: `LICENSE.txt` and `NOTICE.txt` at its top level.
Redistributing the built framework carries the duties of the licences below; where the main repository records
them (its `THIRD-PARTY-NOTICES.md`) is decided there.

Apache-2.0 section 4 applies to the first three rows: the copies of the sources that are modified here, the files
of `cryptokit-src` in the build directory, differ from upstream only in the lines that `DARLING-CHANGES.md`
lists.

**fiat-crypto licence.** BoringSSL's own repository at the revision above has `third_party/fiat/LICENSE`, whose
line 1 reads "The Apache License, Version 2.0 (Apache-2.0)" and line 3 "Copyright 2015-2020 the fiat-crypto authors
(see the AUTHORS file)". `third_party/fiat/README.md` lines 3-5 say that most files of that directory are generated
by Fiat Cryptography and "are included under the Apache 2.0 license. (See LICENSE file.)". Two caveats. First, the
evidence is BoringSSL's upstream repository at the same revision, not the vendored copy: swift-crypto's checkout has no
licence file for `third_party/fiat` and its vendored fiat files carry no header. Second, BoringSSL edits some of the
fiat headers (its README says so); the Apache-2.0 licence covers them as BoringSSL distributes them, and this
file claims nothing more.

**Generated assembly.** 123 of the vendored files are `.S` assembly. 11 of them carry an Apache-2.0 licence header, among them the nine generated files that name Andy Polyakov ("Andy Polyakov <appro@openssl.org> for the OpenSSL project"): `gen/bcm/sha256-armv8-{apple,linux,win}.S`, `gen/bcm/sha512-armv8-{apple,linux,win}.S`, `gen/bcm/sha256-armv4-linux.S`, `gen/bcm/sha512-armv4-linux.S` and `gen/bcm/bsaes-armv7-linux.S`; the tenth file that names him, `crypto/fipsmodule/bn/asm/x86_64-gcc.cc.inc`, has its own Apache-2.0 header (lines 1-12). The other 112 `.S` files carry no licence header. 107 of those say that they are generated from a similarly-named Perl script; of the remaining five, four are `third_party/fiat/asm/*.S` (generated by Fiat Cryptography, see the fiat-crypto row) and one is `crypto/poly1305/poly1305_arm_asm.S`. All 62 perlasm scripts under BoringSSL's `crypto/**/asm` and `perlasm` directories at the revision above carry an Apache-2.0 header (for example `crypto/fipsmodule/sha/asm/sha512-armv8.pl` lines 2-4: "Copyright 2014-2020 The OpenSSL Project Authors ... Licensed under the Apache License, Version 2.0"). No vendored file contains the word CRYPTOGAMS; "CRYPTOGAMS by <appro@openssl.org>" is a string that 27 of those upstream scripts put into the code they generate. For the files without a header the evidence is BoringSSL's upstream repository at the same revision, not the vendored copy.

**Public-domain origin.** Two BoringSSL files say that part of their code comes from public-domain work in SUPERCOP
(<https://bench.cr.yp.to/supercop.html>): `Sources/CCryptoBoringSSL/crypto/curve25519/curve25519.cc:15-18` (the ref10
Ed25519 code of SUPERCOP 20141124, "released as public domain", with other parts replaced by code generated by
fiat-crypto) and `Sources/CCryptoBoringSSL/crypto/poly1305/poly1305_arm.cc:15-16` (the neon2 version in SUPERCOP by
D. J. Bernstein and Peter Schwabe). Both files sit under BoringSSL's own licence header.

**swift-crypto's `NOTICE.txt`.** Apache-2.0 section 4(d) asks a redistributor of a Work that has a NOTICE file to carry
the attribution notices in it that pertain to the work distributed. `NOTICE.txt` of the checkout (the file itself is
the notice, read it there) has three parts: the SwiftCrypto Project's copyright and licence statement, a statement
about Google's wycheproof test vectors (they are in swift-crypto's `Tests`, which are not built here), and this one,
reproduced as written:

> This product contains a derivation of various files from SwiftNIO.
>
>   * LICENSE (Apache License 2.0):
>     * https://www.apache.org/licenses/LICENSE-2.0
>   * HOMEPAGE:
>     * https://github.com/apple/swift-nio

The files that mention SwiftNIO in the checkout are `Sources/CryptoExtras/Util/ThreadSpecific/ThreadOps.swift`,
`ThreadPosix.swift` and `ThreadWindows.swift`. `CryptoExtras` is not compiled into `CryptoKit.framework`, so the
statement may not pertain to the framework; it is carried here anyway, and whether section 4(d) needs it is for the
maintainers to say. The same `NOTICE.txt` refers to a `license` directory with a `LICENSE.<component>.txt` per
component; the checkout has no such directory.

**Installing the licence texts is an open question for the maintainers, and is not done in this change.** The main
repository's `THIRD-PARTY-NOTICES.md` covers source only (lines 3-4). The Helvetica Neue entry (lines 15-18) is a
precedent for installing licence texts with a built file, under `usr/share/licenses`; whether `LICENSE.txt` and
`NOTICE.txt` of swift-crypto (and BoringSSL's licence) should be installed with `CryptoKit.framework` in the same way
has not been decided.
